# Phase 17 AppInspect disposition (4.4.0, precert and cloud tags)

Source: `docs/verification/evidence/phase17/aws-native-x86_64/appinspect/`. Baseline = released v2.0.1 (8 failures). Single package = this PR (9 failures). Cloud tag: 8 and 8.
**This package is not Splunkbase-ready and is not offered for Splunk Cloud.** "Self-distribution" means a customer downloads `netspout.spl` and installs it on their own Splunk Enterprise through Splunk Web.

Result of a message-by-message diff of the precert reports: the only new failure is #9. The messages of the other eight are identical between baseline and single package, apart from the order in which the two accepted Python versions are listed.

## Summary
- Required before self-distribution on Linux x86_64 Splunk Enterprise: none of the nine by AppInspect's own rules. #5 and #8 are deliberate and must stay documented; #9 requires the aarch64 exclusion to stay in the support statement.
- Recommended cleanup: #1, #2, #3, #6, #7 (all interpreter and trigger metadata), done together and followed by the full acceptance suite, since they touch how Splunk starts the app's Python.
- Never fixable for this product: #8 (UDP wire senders) for Splunk Cloud and Splunkbase.
- Not claimed: Splunkbase readiness, Splunk Cloud eligibility, aarch64 support.
