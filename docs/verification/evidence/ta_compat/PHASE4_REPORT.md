## 4. Field ownership (see telemetry_dispatcher.py)
- Proven in the four live runs: an indexed field with the same name as a CIM field hides the add-on's value (ASA: action/src_ip/dest_ip/vendor_action; FortiGate: vendor_action/action/signature; Palo Alto: src_ip/dest_ip/vendor_action/action; IOS: NetSpout values in action/signature/src_ip/dest_ip/protocol).
- Policy: every event carries `netspout_{action,signature,status,src_ip,dest_ip,protocol,vendor,node_type}` copies; sourcetypes with live-verified add-on parsing (cisco:asa, cisco:ios, fortigate_traffic, pan:traffic) send no bare names. Run and scenario correlation (`netspout_run_id`, `netspout_scenario_id`, ...) is unchanged.
- Downstream dependency assessed: three searches in each of the 224 contract dashboards read NetSpout's own status/action/signature; they now read `coalesce(netspout_x, x)` (447 changed searches, 0 parser errors in Splunk). Old searches on TA-owned data returned **0** ASA events; the new ones return all of them.
- Other sourcetypes (73 exact-name matches with a generator) keep the bare names until each is verified.
